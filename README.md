
# PowerShell Workstation Security & Health Audit

## Project Overview

This project demonstrates how PowerShell can collect selected Windows workstation security and health information, identify conditions that may require review, and generate a structured CSV report.

The project uses a read-only audit approach. It does not change Windows settings, disable security protection, modify firewall rules, or delete files.

## Business Scenario

Mahlangu Business Solutions is a fictional company whose IT Support team performs routine workstation checks.

Technicians need a repeatable way to review Windows Defender status, firewall profile states, operating-system information, and available system-drive space.

The audit script collects available information, applies configured review thresholds, and records observations and recommendations.

## Features

- Collects operating-system version and build information.
- Checks available Microsoft Defender status properties.
- Reviews Defender antivirus signature age.
- Inspects Domain, Private, and Public Windows Firewall profiles.
- Checks system-drive free space against a configurable threshold.
- Generates findings and recommended next steps.
- Distinguishes `Pass`, `Review`, `UnableToAssess`, and `Info` results.
- Handles unavailable commands and failed queries without automatically treating them as a pass.
- Exports results to CSV.
- Includes automated tests that validate the report structure and recorded results.
- Avoids recording the computer name, Windows username, and IP address in the report.

## How to Run the Audit

Open PowerShell in the project root directory.

### 1. Run the workstation audit

```powershell
.\scripts\Test-WorkstationSecurityHealth.ps1
```

The script inspects the available status information and generates:

`reports/workstation-security-health-audit.csv`

### 2. Configure the review thresholds

The default minimum free-space threshold is 10%, and the default maximum Defender signature age is 7 days.

You can override these demonstration thresholds:

```powershell
.\scripts\Test-WorkstationSecurityHealth.ps1 -MinimumFreePercent 15 -MaxSignatureAgeDays 3
```

These values are examples for the project, not universal security policy requirements.

### 3. Run the automated tests

```powershell
.\tests\Test-WorkstationAuditReport.ps1
```

The test suite runs the audit, checks that the report is generated, verifies required columns and result statuses, confirms that recommendations are present, and checks that direct machine identifiers are not included as report columns.

During a recorded audit on 23 October 2026, the workstation reported:

- Defender antivirus signatures updated approximately 0.4 days earlier.

The workstation audit report test suite passed 12 checks with zero failures during the recorded test run.

The tests checked:

- Audit script and report availability.
- Required report columns.
- Presence of operating-system, antivirus, firewall, and storage checks.
- Use of documented status values.
- Presence of findings and recommendations.
- Exclusion of direct machine identifiers from the report schema.

These tests validate the report's structure and selected behaviours. They are not a complete security assessment of Windows.

## Safety and Limitations

- The script performs read-only checks.
- It does not remediate findings or change system settings.
- Available commands and returned information vary by Windows configuration and security software.
- A failed or unavailable check does not prove that protection is disabled.
- A check marked `Pass` means only that the queried value met the configured rule.
- The disk-space threshold is a configurable indicator for review, not proof of a disk fault.
- A successful audit does not guarantee that every possible security issue has been detected.
- Audit output may contain system details, such as Windows version and disk capacity. Review the generated report before publishing it.
